# Changelog

## Unreleased

- **TCP BBR/FQ и swap больше не останавливают установку.** v0.4.3 падала на preflight с `TCP BBR/FQ is already configured in a foreign persistent sysctl file`, если BBR уже включён VPS-Server-Menu: оно дописывает `net.core.default_qdisc=fq` и `net.ipv4.tcp_congestion_control=bbr` в `/etc/sysctl.conf`. Такая же остановка ждала чужой `/swapfile` размером не 2 ГиБ (VPS-Server-Menu создаёт 1, 2, 4 ГиБ или произвольный).
- BBR/FQ работает по той же схеме, что IPv6: `managed` / `external` / `skipped` в `state.bbr.mode`. Уже применённая чужая настройка — `external`, Bob ничего не пишет. Контейнер, ядро без BBR, противоречащие значения или сбой с откатом — `skipped` с предупреждением. Чужой swap не трогается (`external`/`skipped`). Установщик выводит отдельную строку по IPv6, BBR/FQ и swap и продолжает.
- Откаты BBR и swap выполняются и при Ctrl+C, откат BBR перечитывается. Неподтверждённый откат остаётся фатальным. Убран `except Exception: pass` из отката BBR.
- Исправлено: v0.4.3 печатала `✓ TCP BBR/FQ: настроены.`, не проверяя результат BBR.
- Acceptance проверяет BBR/FQ только в режиме `managed`. Doctor читает `state.bbr`: внешняя настройка — `PASS`, пропущенная — `SKIP`, чужой swap — `SKIP`. Ноды без `mode` проверяются, как раньше.

## v0.4.3 — 2026-11-04 · Preview

- **IPv6 — best effort.** Установка больше не останавливается на preflight с `Foreign persistent IPv6 sysctl assignment`, если IPv6 уже отключён другим инструментом: совпадающие назначения `disable_ipv6 = 1` (так их пишет `ipv6-menu` VPS-Server-Menu в `/etc/sysctl.conf`) не считаются конфликтом. Так упала установка v0.4.2 на VPS, где IPv6 был отключён через VPS-Server-Menu.
- Результат этапа записывается в `state.ipv6.mode`: `managed` — политика Bob применена и проверена; `external` — IPv6 уже выключен чужой конфигурацией, Bob ничего не пишет; `skipped` — настроить IPv6 безопасно нельзя (противоречащие `disable_ipv6 = 0`, IPv6 SSH, не netplan/networkd, сбой с полным откатом), чужие файлы не изменяются. Установщик пишет `⚠ IPv6: настройка пропущена — …` и продолжает. IPv4-only объявляется только в `managed`.
- Без политики Bob установка продолжается, только если UFW фильтрует IPv6 (`IPV6=yes`) и через маршрутизируемый IPv6 слушают лишь SSH, 80 и 443; иначе это фатальный отказ. Проверка повторяется при раннем и позднем resume и в acceptance. DNS с AAAA, проверки IPv4, symlink и изменённые файлы Bob по-прежнему фатальны.
- Откат частичной настройки IPv6 теперь проверяется повторным чтением sysctl и файлов и выполняется и при Ctrl+C. Неудачный откат остаётся фатальным.
- BBR/FQ и swap настраиваются до IPv6 и не зависят от него. Сбой IPv6 их не отменяет, сбой BBR IPv6 не затрагивает.
- Bob Doctor различает режимы. `external`: `PASS`, пока IPv6 выключен, иначе `WARN`. `skipped`: всегда не выше `WARN`. В обоих режимах IPv6 при UFW без IPv6 — `FAIL`. Ноды с прежним state читаются как `managed` и проверяются, как раньше.
- Команда установки стала короче: `curl -fsSL --proto '=https'`. Флаг `--proto-redir` был лишним, потому что `--proto '=https'` уже запрещает редирект не на HTTPS.

- Ответ Let’s Encrypt `rateLimited` «Service busy; retry later» — перегрузка сервера, частая на staging, — теперь считается временной ошибкой: проверка продления повторяется в прежних пределах (4 попытки, 20 минут). Раньше он принимался за лимит домена: повторов не было, а сообщение ошибочно называло «лимит повторных сертификатов». Так упала установка на VPS 2026-11-04 (v0.4.2). Настоящие лимиты (повторные сертификаты, неудачные проверки, регистрации) по-прежнему не повторяются и теперь называются по своему виду.

- Xray-core обновлён до официального v26.10.31 (`a4a3dff`) — срочного релиза безопасности: по умолчанию отключён MPTCP у слушающих сокетов, так как в ядре Linux найдена удалённо эксплуатируемая уязвимость IPv4 MPTCP, а Go 1.24+ включает MPTCP по умолчанию. Upstream рекомендует также обновить ядро. Закреплены SHA256 архивов amd64/arm64 (совпадают с официальными `.dgst`) и извлечённых бинарных файлов; установщик и acceptance проверяют версию и commit.
- Между 26.10.21 и 26.10.31 в Xray ограничен native GeoData updater (только существующие файлы `.dat`, интервал не меньше минуты, до 256 MiB); конфигурация Bob — четыре `.dat` из 3x-ui и суточный cron — ему соответствует. 3x-ui остаётся v3.11.0; её встроенный Xray 26.10.21 заменяется до первого запуска, как и прежде.
- Уже установленные ноды автоматически не обновляются. VPS E2E с Xray 26.10.31 не проводился.
- **Resume после сбоя на этапе SECURITY.** Временная сетевая ошибка при проверке продления (например, `ConnectionResetError` от ACME staging) больше не делает почти готовую установку невосстановимой: повторный запуск продолжает с первого незавершённого шага SECURITY и проходит acceptance, не повторяя APT, BBR, firewall, WARP, Certbot, nginx и установку панели. State и система сверяются до любых изменений; несовпадение или повреждённый state — отказ. Прежде простое добавление SECURITY в allowlist повторило бы BBR, firewall, выпуск сертификата, генерацию портала и переустановку 3x-ui.
- Проверка продления изолирована: только сертификат Bob (`--cert-name`) и только hook Bob (`--no-directory-hooks --deploy-hook …/50-selfsni`); посторонние pre/post/renew hooks в renewal-конфигурации Bob или `cli.ini` — отказ. Упавший, пропущенный или незапущенный hook не даёт PASS, даже если certbot завершился с кодом 0. Штатное продление через `certbot.timer` и каталог hooks не изменено.
- Повторяются только временные сетевые ошибки ACME (до 4 попыток, 20 минут). Ошибки HTTP-01, deploy hook, TLS-проверки и rate limit сообщаются отдельно и без повторов. Ложного PASS нет: без подтверждённого dry-run установка не завершается.
- Поздний resume не обновляет Xray: acceptance сверяет ядро с проверенным при установке (SHA256 и версия из state), поэтому нода, установленная v0.4.2 с Xray 26.10.21, доводится до `HEALTHY_LOCAL` и этим релизом; установщик предупреждает, что ядро отличается от закреплённого 26.10.31. Свежая установка по-прежнему требует 26.10.31.
- Поздний resume не изменяет сетевую конфигурацию: IPv6-политика только проверяется, расхождение — отказ.
- **Resume с этапа CERTIFICATE после выпуска сертификата.** Если сбой случился уже после успешного `certbot certonly` (ошибка `certbot.timer`, таймаут после сохранения, Ctrl+C), resume отвергал собственный сертификат Bob как «чужой», и восстановить установку можно было только удалением сертификата и перевыпуском (лимит Let’s Encrypt — 5 одинаковых в неделю). Теперь принимается ровно lineage Bob, а `certonly` идёт с `--keep-until-expiring` и действующий сертификат не перевыпускает.
- **Повтор перезагрузки TLS после продления.** Certbot запускает deploy hook один раз и только логирует его ошибку; при сбое nginx и x-ui продолжали бы отдавать старый сертификат до его истечения. Hook теперь пишет отметку успешной перезагрузки, а drop-in `certbot.service` при каждом запуске `certbot.timer` повторяет hook, пока сертификат новее отметки; сбой виден как failed `certbot.service`.
- Doctor предупреждает о сроке сертификата, только когда продление запаздывает (относительно срока жизни сертификата), поэтому не даёт ложных `WARN` после перехода Let’s Encrypt на 64 и 45 дней при certbot 4.0 (Ubuntu 26.04).
- **Ubuntu 22.04 больше не поддерживается** (certbot 1.21 без `--run-deploy-hooks`); preflight её отклоняет. Поддерживаются Ubuntu 24.04 (certbot 2.9.0) и 26.04 (certbot 4.0.0). CI проверяет командную строку dry-run на пакетном certbot обеих ОС.

## v0.4.2 — 2026-11-01 · Preview

- `bob admin` подтверждает клиента admin в runtime Xray на штатной установке. Раньше всегда показывалось «не подтверждено»: официальный установщик 3x-ui распаковывает архив через `tar` от root и сохраняет владельца из архива (uid 1001) у `/usr/local/x-ui` и `bin/`, а CLI требовал root-владельца каждого каталога пути. Для runtime-конфигурации владелец каталогов больше не проверяется; symlink, запись для group/other и требования к самому файлу (обычный, root, `0600`) сохранены, проверки `state.json` не изменились. Сопоставление идёт той же функцией, что в установщике (`verify_admin_runtime`): `PASS` — подтверждён, `WARN` — отсутствует или отличается, `UNKNOWN` — с причиной.
- Обновление только CLI на работающей v0.4.0/v0.4.1 — прежним `install.sh cli-upgrade [--check]` из этого релиза; VPN, службы и state не затрагиваются. Изменён только CLI, provision и Doctor те же, что в v0.4.1.

## v0.4.1 — 2026-11-01 · Preview

- **Меню `bob`.** Обычная команда `bob` в терминале открывает компактное меню на русском: доступ к панели, подписка admin, Bob Doctor, глубокая диагностика, состояние сервера и сводка отчёта установки. Все пункты только читают; restart, update, backup и другие изменяющие операции не добавлялись.
- Новые команды: `bob panel`, `bob admin`, `bob status`, `bob report`, `bob --help`, `bob --version`. Без терминала `bob` печатает справку и не ждёт ввода. `bob doctor [--deep] [--json]` делегируется прежнему Doctor без изменений: формат JSON и exit codes 0–3 те же; `bob --json`/`bob --deep` из v0.4.0 тоже работают.
- Секреты (URL панели, исходные логин и пароль, ссылка подписки admin) берутся только из root-only `/var/lib/selfsni/state.json` и показываются после явного подтверждения; без терминала — только с флагом `--show-secrets`. Чтение без symlink в пути, только обычный файл root `0600` с одной ссылкой; state проверяется той же валидацией, что и в Doctor. В логи, JSON и другие файлы секреты не попадают; после показа меню очищает экран и scrollback (в терминалах с ANSI).
- Пароль показывается как исходный из установки: если его меняли в 3x-ui, он не действует. Текущий пароль из хэша не извлекается, автоматического сброса нет. Для admin меню дополнительно сверяет наличие клиента в runtime Xray.
- **Обновление только CLI на работающей v0.4.0:** `install.sh cli-upgrade [--check]` из проверенного архива релиза. Заменяются только `/usr/local/bin/bob` и `/usr/local/lib/bob-auto-xray`, и только если их содержимое доказывает принадлежность Bob: wrapper побайтно совпадает с записанным Bob, библиотека — с деревом релиза v0.4.0 (SHA256) или со своим манифестом. Чужие или изменённые файлы не трогаются. Замена атомарная (rename), после неё проверяется запуск новой команды, при любой ошибке — откат. Provision, службы, state и конфигурация VPN не затрагиваются; установщик и обновление взаимно исключены его lock. Существующие установки автоматически не мигрируют.
- Новые установки кладут в библиотеку CLI `VERSION` и манифест `.bob-cli.json`; правило «имя `bob` не перезаписывается» сохранено.

## v0.4.0 — 2026-11-01 · Preview

- **Bob Doctor** (`bob doctor [--deep] [--json]`): read-only диагностика установленной ноды без автоматического исправления, рестартов, изменяющего API 3x-ui и acceptance. Проверяет state, Xray runtime и SHA256 закреплённого ядра, службы и gate x-ui, listeners и UFW, маршруты nginx HTTPS/443, сертификат, routing, GeoData, WARP, BBR/FQ, IPv6, SWAP, постоянного клиента `admin` и остатки временных файлов state. Недостаток данных — `UNKNOWN`, никогда не `PASS`; FQDN, секретные пути, UUID, ключи и хэши в отчёт не попадают. `--deep` ограничен GET, trace и белым списком read-only команд.
- Старые ноды не получают ложный `UNHEALTHY`: схема определяется по маркерам state (`panel_access`, `admin_client`, `subscription_access`), политики, которых нода не получала, дают `WARN`. На уже установленной ноде Doctor запускается из проверенного архива: `install.sh doctor`. Установка `bob` не может сорвать установку VPN, результат записывается в state (`doctor_cli`).
- **Исправлен возврат IPv6 после reboot.** Причина доказана на VPS журналом networkd: установщик работает с umask 077, каталог drop-in `/etc/systemd/network/<netplan>.network.d` создавался `0700`, и systemd-networkd (пользователь `systemd-network`) не мог его прочитать (`Permission denied`), настраивал интерфейс по исходному netplan-файлу и записывал `disable_ipv6=0`. Теперь каталог `0755`, acceptance отказывает при нечитаемом drop-in. После исправления и reboot IPv6 на интерфейсе выключен, адресов нет.
- Уже установленные ноды (v0.3.4–v0.3.8) автоматически не мигрируют: Doctor показывает `WARN` с точной командой `chmod 755 /etc/systemd/network/<netplan>.network.d`, после неё политика сохраняется при reboot.
- Doctor разделяет маршрутизируемый IPv6-адрес (`FAIL`) и только link-local при `disable_ipv6=0` (`WARN` с числом адресов и именами интерфейсов, сами адреса не печатаются). Resume с этапов `WARP`/`CERTIFICATE` заново применяет IPv6-политику до acceptance.
- Preflight не начинает установку, пока cloud-init ещё настраивает свежую VPS, и просит дождаться `cloud-init status --wait` вместо непонятного `sshd exited 255`.
- 3x-ui обновлена до официального v3.11.0 (`c621ba9`): SHA256 архивов amd64/arm64, vendored `x-ui.sh` и `x-ui.service.debian` с тега, SHA256 штатных GeoData. Встроенный Xray совпадает с отдельно закреплённым официальным v26.10.21; проверенная замена ядра сохранена.
- Nginx отвечает на `<webBasePath>sponsors` пустым JSON-списком и 404 на `<webBasePath>sponsors/logo/`: спонсорские блоки панели пусты, логотипы не загружаются. Бинарный файл 3x-ui не изменяется.
- WARP: установленный `warp-cli` требует `--accept-tos` и для JSON status/settings; эти запросы не меняют регистрацию и настройки.
- HTTPS/443, секретный webBasePath, TLS verification upstream, подписки, `vless by bob`, `admin`, ads block, routing/WARP и модель resume сохранены. Установленные ноды автоматически не мигрируют.
- VPS E2E финального кандидата на Ubuntu 26.04.1 amd64: [E2E-V040.md](docs/E2E-V040.md).

## v0.3.8 — 2026-10-31 · Preview

- VPS-Server-Menu получает актуальную официальную main во время установки Bob, без статического commit/SHA256 pin или скрытого fallback. Остальные зависимости остаются pinned.
- Checkout /root/VPS-Server-Menu находится на main tracking origin/main. Bob вызывает оригинальный install.sh с --non-interactive --no-autostart --source-dir, без --pinned-commit. Штатные команды/symlinks и пункт 9 обновления сохраняются.
- Проверяются origin, branch/upstream, чистота и обычные файлы/каталоги, конфликтующие команды и CLI contract. Существующая main продвигается только fast-forward; dirty/unknown/diverged state, network/installer/CLI errors прекращают установку. Нет reset --hard, clean или замены чужого origin.
- Фактические origin/branch/full SHA и UTC resolution time сохраняются root-only в menu_revision. Один релиз Bob в разные дни намеренно может установить разные upstream revisions; совместимость будущего upstream не гарантируется. Runtime WARP health/JSON/exit/outbound и независимый warp=on acceptance сохранены.
- Без VPS/SSH/deploy/reboot. Старая detached pinned установка меню требует ручного решения: Bob не переключает её branch принудительно.

## v0.3.7 — 2026-10-31 · Preview

- State marker subscription_access=https-443 управляет публичными URL. Старый state без маркера сохраняет URL с отдельным портом; автоматической миграции v0.3.6 и других завершённых установок нет.
- Сохранены vless by bob, постоянный admin, GeoSite ads block, routing/WARP, pinned components, panel/decoy, IPv6/BBR/swap и модель installer resume. VPS E2E/reboot этой версии не выполнялись; исторические результаты не приписываются новой сборке.

## v0.3.5 — 2026-10-31 · Preview

- Панель новых установок доступна на `https://<domain>/<48-hex-secret>/` через существующий REALITY TCP/443 → PROXY v1 → Nginx Unix socket. HTTPS upstream 3x-ui привязан только к `127.0.0.1`; отдельный публичный admin port отсутствует. Заглушка, API, WebSocket, подписки и точный REALITY Target сохранены; старые установки автоматически не мигрируют.
- Перед первым стартом панели проверяются сохранённые TLS/listen IP, internal port, webBasePath и отсутствие стандартной пары admin/admin, затем загружается сертификат/ключ. Несовпадение после exit-zero ошибки CLI оставляет service gate закрытым. Настоящий вход с сгенерированными credentials проверяется acceptance.
- IPv6: в управляемый networkd drop-in добавлен `IPv6LinkLocalAddressGenerationMode=none`, конфликтующий чужой параметр отклоняется. Проверка адресов теперь включает link-local; регрессии моделируют повторную инициализацию интерфейса, отказ проверки, повторное применение и rollback. Это обоснованное усиление политики, **не подтверждение устранения исторического P1 после reboot**: точная причина того сбоя остаётся не установлена без наблюдения на VPS.
- Для воспроизводимости между версиями Python явно закреплён gzip compresslevel=9 (Python 3.15 изменил default).
- Генератор notes использует раздел текущей версии CHANGELOG вместо истории v0.3.4. Release workflow выполняет Nginx harness, compileall и проверку воспроизводимости, как CI.
- Закреплённые версии Xray, 3x-ui, WARP menu и routing не изменены. WARP install/adopt/skip, routing presets, GeoData, BBR/FQ, resume и root-only данные сохранены. Bob Doctor из PR #11 исключён.
- Чистую установку и reboot финального v0.3.5 проверит владелец вручную после публикации; новые VPS E2E не проводились.

- На этапе IPv6 и BBR/FQ добавлена необязательная установка swap-файла `/swapfile` на 2 ГиБ. Он создаётся только при запасе не менее 2 ГиБ свободного места после выделения файла, включается сразу и закрепляется в `/etc/fstab`. Уже существующий swap-файл не удаляется и не перезаписывается; при нехватке места этап пропускается. Доступны read-only preflight, проверка результата и откат при ошибке.

На уже установленной одноразовой VPS проверены preflight, применение, настоящий reboot, IPv4 SSH, BBR/FQ, WARP и внешнее REALITY/Vision-соединение с существующим клиентом. Чистая установка с новым IPv6-этапом не выполнялась.

- Исправлено продолжение после Certbot: удалено создание неиспользуемого приватного ACME-каталога, из-за которого повтор на этапе `CERTIFICATE` останавливался с `File exists`. Реальная VPS проверка с контролируемым отказом Certbot подтвердила сохранение installation ID и credentials до успешного resume.
- На отдельной чистой Ubuntu 26.04.1 VPS проверен `--adopt-warp` с заранее работающим официальным Cloudflare WARP: полная установка, фактический `xray run -test`, on-host 27/27 и внешний REALITY/WARP 7/7 до и после reboot. При установке регистрация, настройки, PID и счётчик рестартов WARP не изменились. Первую попытку остановил внешний лимит повторного сертификата Let’s Encrypt; успешный E2E выполнен после сброса VPS с другим доменом.
- GeoData E2E теперь проверяет rollback на `geosite_RU.dat`, который действительно используется правилами режима без WARP. Ожидание журналов привязано к cursor, а восстановление дожидается готовности панели. Штатный updater Xray прошёл успешную загрузку, HTTP 404 и невалидный HTTP 200 с rollback без собственного сервиса обновления.
- Xray-core закреплён отдельно от 3x-ui: официальный v26.10.21 для amd64/arm64, проверка SHA256 архива и извлечённого бинарного файла перед заменой ядра панели. Панель остаётся v3.10.2; её встроенный Xray 26.10.10 заменяется до настройки и итогового запуска. Acceptance проверяет digest, версию и реальный `xray run -test`.
- Добавлены три режима WARP: install (по умолчанию), read-only adopt и skip (`--no-warp`). В skip нет WARP outbound/rules, зависимости x-ui от warp-svc, проверки `/dev/net/tun` и обязательного пакета cloudflare-warp; уже установленный сторонний WARP не изменяется.
- Проверка bundle в adopt/skip не требует WARP keyring; повторная общая проверка в середине установки удалена. Несовместимый upstream WARP API не блокирует режим skip.
- Режим WARP сохраняется в state и защищён от незаметной смены при resume. Старые state с `adopt_warp` читаются без смены installation ID и credentials; пропущенный этап WARP осознанно отмечается завершённым.
- Режимы server routing, on-host acceptance и внешнего E2E разделены; блокировки RU/UA/private/BitTorrent и клиентские Happ/INCY presets сохранены. Новый WARP использует закреплённый официальный API.
- APT разделён на `update`, обычный `upgrade` и `install`: штатное ожидание dpkg lock до 10 минут, ограниченные повторы только временных ошибок репозитория и точная классификация lock/network/dependencies/dpkg/systemd/timeout.
- Добавлены redacted diagnostic log 0600, installation lock и state machine с сохранением credentials. Подтверждённые сбои APT, частичная установка WARP и retry Certbot безопасно продолжаются той же командой; поздние неоднозначные стадии автоматически не возобновляются.
- Добавлен русскоязычный TTY-мастер, ASCII/non-TTY fallback и `NO_COLOR`; release bootstrap больше не показывает progress bar curl.
- Вопросы установки переписаны понятным языком, с примерами, предупреждением о системных изменениях и подтверждением. Указанные CLI-значения не спрашиваются повторно; сохранённая установка продолжает работу без повторного мастера.
- Живой прогресс считает только завершённые этапы; длительные команды показывают время и индикатор активности, non-TTY вывод остаётся обычным текстом. Вывод команд сохраняется в root-only журнале, тайм-аут и Ctrl+C останавливают процесс.
- Ошибки Certbot классифицируются по ответу ACME; подтверждённое время снятия лимита переводится из UTC в МСК без догадок. Состояние после сбоя сертификата сохраняется для resume.
- Убрано предупреждение APT по одному лишь процессу `unattended-upgr`; реальное ожидание lock отображается по выводу APT однократно. Сохранены `DPkg::Lock::Timeout=600`, индикатор активности и полный защищённый журнал.
- Финальный экран больше не показывает ссылку на подписки при нуле клиентов, объясняет создание первого клиента и выводит реквизиты только в интерактивном терминале.
- Официальный VPS-Server-Menu закреплён на `3ed5166bbc5b4fb4cc3bb26616bc4db3bbe2734c` и SHA256 `9d7a2aced39fe206a9cb4cd46481ee6876471458a63988b9fca152238fa7ec29`. Bob проверяет codeload-архив, origin/HEAD/чистоту checkout и symlink-конфликты до APT; сравнивает Git checkout с архивом, запускает официальный установщик без автозапуска и принимает только согласованные JSON/exit codes install и health. Режим adopt использует только health, skip не загружает меню.
