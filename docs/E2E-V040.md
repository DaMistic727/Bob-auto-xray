Доступ по выделенному ключу, host key сверен с консолью владельца. Новый FQDN с одной A-записью, без AAAA. ## Ограничения и отклонения

- **Внешняя изоляция внутренних портов — INCONCLUSIVE.** Из сети наблюдателя TCP «соединяется» с любым портом любого адреса (включая `1.1.1.1:54321`), значит наблюдение недостоверно. Серверная сторона подтверждает изоляцию: подключение к публичному IP на порты панели и подписок — `ConnectionRefused`, на loopback — успешно; правила UFW только 22/80/443.
- **C2:** «выживание» сессии, начатой до рестарта, не заявляется: данные успели попасть в буфер клиента до рестарта. Обрыв активных соединений при рестарте Xray ожидаем; проверено восстановление новых.
- **RC2 не устанавливался с нуля** (для этого нужна переустановка ОС). Изменение RC2 ограничено `ipv6.configure/verify` и Doctor; на VPS выполнен именно этот код под `umask 077` и reboot.
- Перед установкой выполнен reboot в обновлённое cloud-init ядро (`7.0.0-42`). Для расследования включены persistent journal и debug-уровень systemd-networkd (вне путей Bob).
- **NOT TESTED:** Ubuntu 22.04/24.04, arm64, `--no-warp`/`--adopt-warp` этой сборки (Doctor в этих режимах проверен на `4428fd8`, [E2E-PR11-DOCTOR.md](E2E-PR11-DOCTOR.md)), resume после настоящего прерывания с reboot, продление сертификата, мобильные клиенты, доставка опубликованным bootstrap по сети (до публикации релиза; bootstrap проверен через shim).
